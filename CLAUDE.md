# Voice Commands: project notes for Claude

> [!NOTE]
> **About this file:** `CLAUDE.md` holds the instructions that Claude Code reads when it works on this project: its layout, the development mode and the design decisions that must stay. It is not a user guide. To install and use Voice Commands, read the [README](README.md). If you change the project with Claude Code yourself, Claude follows these notes, so keep them up to date.

Spoken commands for Claude Code on Arch Linux. Talk to the user in their language, which is German.

## Layout

- `bin/`: `voice-commands` (recording, speech recognition, runs Claude), `voice-commands-bg` (invisible Xvfb display for background programs), `voice-commands-permission` (decides each tool use), `voice-commands-ask` (its yes or no window; zenity if it cannot be shown), `voice-commands-input` (window to type a command), `voice-commands-commands` (which commands run without asking), `voice-commands-theme` (shared look), `voice-commands-overlay` (status bar), `voice-commands-window` (response window), `voice-commands-markdown` (Markdown for the response window, notifications and reading aloud), `voice-commands-speak` (reading aloud with Piper or the system voice), `voice-commands-shortcuts` (writes and checks the shortcuts on Hyprland, KDE Plasma and GNOME), `voice-commands-setup` (per-user setup).
- `hypr/`: Hyprland shortcuts in Lua.
- `desktop/`: launcher entry and icon for the response window.
- `packaging/`: `PKGBUILD`, `voice-commands.install` and `build-package.sh`, which builds the flat package folder `aur/` (ignored by git; there is no AUR release).
- `skill/SKILL.md`: instructions installed for Claude Code on each computer.
- `CHANGELOG.md`: every notable change since the first public release (1.13.0), newest first; fixes record cause and solution, so that earlier fixes can be found again. Add an entry under Unreleased with each change, and read it first when a problem looks familiar. Changes before that release are in `CHANGELOG.local.md`, which is not in the repository; read it too if it exists.
- `tests/permission-hook.sh`: tests for the permission hook, the command lists and the protected area of background programs; run them after every change to any of them, and add a case for each new rule.
- `help/`: help (`de.md`, `en.md`) and the short welcome shown when the response window opens for the first time (`welcome.de.md`, `welcome.en.md`). `{toggle}`, `{cancel}`, `{window}`, `{send}` and `{type}` are replaced by the current shortcuts. Keep both languages up to date whenever a feature changes.

Runtime data is in `~/Voice-Commands`, speech models and the history of the response window (`antworten.jsonl`, moved there from `~/Voice-Commands` so that Claude and background programs cannot change it unasked) are in `~/.local/share/voice-commands`.

## Development mode

`bin/voice-commands-setup` started from a copy of the source links the programs into `~/.local/bin` and points the Hyprland loader, the launcher entry and the Claude Code instructions there, so changes take effect right away (the response window after reopening). `/usr/bin/voice-commands-setup` switches back to the installed package. Do not set up passwordless `pacman` or a root service to install automatically: anything running as the user, including Claude during a voice command, could then become root. Build and install the package only to test packaging or before publishing; new dependencies still need the user to install them.

Private notes about this maintainer's computer and the current status are in `CLAUDE.local.md`, which is not in the repository. Read it first if it exists, and keep personal or status information there, not here.

## Decisions to keep

Each point is a decision of the maintainer. Do not change or undo one without asking them first.

- The name stays descriptive, not a made-up name, and it must not contain Claude or Anthropic.
- Commit only with the anonymous address configured in this repository. The repository is public: never commit personal data, credentials or status notes.
- Setup and update messages are in plain English. Notifications, status bar and response window follow the system language (German and English). Claude replies in the language of the command.
- `voice-commands-permission` decides each tool use: `~/Voice-Commands` needs no permission, reading or writing anywhere else and other commands show a yes or no dialog, and no answer or any failure means no. Reads ask as well. The dialog can also give all permissions for the current request after a second confirmation with a warning, except that secret places keep asking. Folders shared for good in the settings (`folders` in `settings.json`, each read only or read and write, as in the desktop app) need no dialog for reading, and for writing if allowed; commands still ask, secret places still ask, and writes to protected places (shell, desktop, editor and terminal startup files, `~/.config/user-dirs.dirs`, `~/.claude`, `~/.config/voice-commands`, Git hooks, the Voice Commands programs and source folder) still ask, so that Claude cannot widen its own rights. Background programs start and are operated without a dialog, but run in bubblewrap with the home folder as an overlay (only `~/Voice-Commands` and shared folders with write access are written for real, except a shared home, folders containing it and hidden folders in it; `.git` folders and the source folder stay read only; downloads go to `~/Voice-Commands/Downloads`, Voice Commands' runtime folder is hidden; needs the kernel module `overlay`, loaded by the package through modules-load.d), the secret places (`SECRET_PLACES`, the same list in `voice-commands-permission` and `voice-commands-bg`, checked by the tests) emptied other processes hidden, the runtime folder (D-Bus, Hyprland and Wayland sockets) empty and only the invisible X display reachable, and never start without it; programs with script functions (LibreOffice, GIMP …) are deliberately not refused, the README names this; `voice-commands-bg` refuses editors, IDEs, file managers and terminals, and `start` with any argument other than an `http(s)` address asks; the README says that a running program can still be operated freely and reaches all other files. `/` cannot be shared, and sharing the home folder, a system folder or a hidden folder in home (such as `~/.config`), or allowing changes, needs a confirmation with a warning. The settings always show tips on what to watch out for. Spoken commands have a chance to cancel, 5 seconds by default, which can be turned off and skipped with the send shortcut. Typed commands start right away. New files must go into a subfolder of `~/Voice-Commands` by topic: the hook denies a new file directly at its top, and responses list the files written during the command. Commands in the lists of `voice-commands-commands` run without a dialog when called plainly: built-in system information, and reading file commands with a reach chosen per command (working folder, shared, personal, home without hidden folders, system files, everywhere or own folders), each switchable off, with a confirmation for home, system files and everywhere that says secret places are only recognized by known names and other access data is read without a dialog, and own commands from the settings with a warning and confirmation, where known reading programs (`SCOPABLE`) get a reach to choose like the built-in file commands and all others reach any place named; own commands are at the user's own risk: only programs that run any command they are given (sudo, shells, interpreters, env …) are refused, other known risks are named when adding, and the warning gives no examples of safe commands; and writing into any `.git` folder asks, also in `~/Voice-Commands`, because Git runs programs named in `.git/config` even for `git status`. Do not add unattended loops without discussing Anthropic's terms on automated access.
- Every voice command gets a current list of Claude's permissions (`voice-commands-commands permissions`), generated from the applied settings and the same lists the hook uses; it grants nothing and tells Claude not to use these ways to get around a dialog.
- Claude Code's automatic memory is off for voice commands, so that nothing a command hears is kept beyond the conversations, which are deleted after the chosen days.
- Commands use the default model from Claude Code, unless a model is chosen in the response window, which is stored in `~/.config/voice-commands/model`. Automatic model selection was tried and removed, so do not add it back unless asked.
- Settings from the gear button in the response window take effect only when applied in the bar at the bottom of the settings, so that nothing changes by a slip; they are stored in `~/.config/voice-commands/settings.json`: reading aloud (off by default), what and how fast to read, spoken language, time to cancel (off, or at least 3 seconds), how long a new command continues the last conversation (`followup`: off, 5, 15 or 30 minutes, default 5, because a long conversation once made Claude save files nobody asked for) and opening the window when done. Claude's instructions say to make files only when asked or when the result has to be a file. The model choice stays in its own file. Reading aloud prefers Piper (`piper-tts` from the AUR, or `pipx install piper-tts`, which puts `piper` in `~/.local/bin`; voices from `voice-commands-setup`) and falls back to speech-dispatcher or espeak-ng.
- Nothing may pile up: the history keeps 50 responses, the log 1000 lines, and screenshots are kept in `$XDG_RUNTIME_DIR/voice-commands-bg/shots` (memory, emptied at shutdown) and deleted when the background programs close; the permission hook lets Claude read, not write, that folder. Claude Code's session files keep everything Claude read, including screenshots, so `voice-commands` deletes its own sessions (only UUID-named files and folders in Claude Code's project folder for `~/Voice-Commands`) after the days chosen in the settings: 1, 7 or 30, default 7. Temporary files go to `$XDG_RUNTIME_DIR/voice-commands`. Files Claude saves in `~/Voice-Commands` belong to the user and are never deleted automatically.
- The response window opens a session in the desktop app with `claude://resume?session=<id>`. Anthropic documents this handoff only for macOS and Windows, and `claude --desktop` refuses on Linux, so it can break with an update.
- Keep it working on any Arch-based system.
- Shortcuts are set in the response window and stored in `settings.json`. `voice-commands-shortcuts write` turns them into `~/.config/voice-commands/shortcuts.lua` (read by the package file). Only Hyprland's Lua settings are supported (`hyprland.lua`, Hyprland 0.55 or newer); the classic `hyprland.conf`, which newer versions still load, is not supported, so check for `hyprland.lua`, not the version. `hyprland.lua` loads `pcall(require, "config.voice-commands")`, which is the user's own loader with `pcall(dofile, ...)`, not a link into the package: a link made Hyprland reload while pacman replaced the file, and the failed `require` broke the whole config. Because errors are caught, Voice Commands warns itself: the loader reloads once after 5 seconds if the package file is missing and warns if it is still missing, the package file warns about shortcuts that cannot be bound, and the response window shows a banner if `voice-commands-shortcuts check` finds a missing or doubly used shortcut. On KDE Plasma, the setup and the settings set the shortcuts too: one hidden launcher entry per action (`~/.local/share/applications/local.voicecommands.<action>.desktop`), registered with kglobalaccel over D-Bus, which applies changes at once. Plasma keeps its own shortcuts in `shortcuts_kde` with the defaults Meta+H, Meta+Shift+H, Meta+Alt+H, Meta+Ctrl+H and Meta+J, because Plasma uses Meta+G and Meta+I; Hyprland keeps the G keys. Never take over keys Plasma already uses, and never start kglobalaccel outside Plasma. On GNOME, the shortcuts are GNOME custom shortcuts in gsettings (`.../custom-keybindings/voice-commands-<action>/`), stored as `shortcuts_gnome` with the G keys as defaults; the user's own custom shortcuts must stay.
- `sudo` needs the user's password, so give the user those commands to run.
- Look, made to suit a tool for Claude: warm paper tones with an own copper accent in `voice-commands-theme`, light and dark (setting `appearance`: system, light, dark), font JetBrains Mono. For copyright and to avoid suggesting a connection, never use Anthropic's logo, wordmarks, fonts (Styrene, Tiempos, Copernicus) or copy claude.ai's interface; the icon is Voice Commands' own microphone.
- Windows of Voice Commands detach from the terminal with a double fork before GTK loads, because Hyprland's window swallowing, if turned on, otherwise hides the terminal they were started from. Keep this for any new window; the status bar avoids it as a layer-shell surface.
- The yes or no window preselects No, enables Yes only after one second, and counts closing, Escape, timeout and any failure as no; exit 3 means it could not be shown and the hook falls back to zenity.
- Deleting a response in the response window deletes its Claude Code conversation too (`voice-commands delete-session`, which waits for the task queue), after the undo toast ends or the window closes. If other responses share the conversation, a dialog lists them and offers deleting the whole conversation or only removing the response from the overview, with the note that Claude Code keeps it until the retention time. History changes take `$XDG_RUNTIME_DIR/voice-commands/history.lock`. Clear history deletes all of these conversations too (`voice-commands delete-all-sessions`), but never files in `~/Voice-Commands`.
